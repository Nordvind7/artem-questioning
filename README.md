# Artem Questioning

**Навык для Codex и Claude Code, который помогает понять, что проверять следующим и когда данных уже достаточно для решения.** Подходит для диагностики, постановки сложной задачи и мозгового штурма. Работает на русском языке в одной модели. Для большой задачи хранит вопросы и свидетельства в локальном файле.

> На сайте психолога стало 21 событие «заявка» вместо 40. Стоит ли отключить мобильную рекламу?

В учебном примере сервер принял те же 40 форм. Сверка по ID показывает две потери одновременно. Десять мобильных заявок дошли до администратора и пропали из аналитики. Ещё девять пропали и из CRM, и из аналитики. Первое действие — вернуть девять обращений. Когда те же 20 мобильных обращений доходят до CRM, ответ меняется: первым исправляют учёт. [Разобрать кейс самостоятельно](examples/appointments/CASE.md) · [Посмотреть ход проверки](examples/appointments/RESULT.md)

## Установка

Скачайте ZIP через **Code → Download ZIP**, распакуйте, откройте терминал в папке с этим README и выполните команду для своего клиента. Если пользуетесь Git, можно клонировать репозиторий. Для утилит используйте Python 3.9+ на macOS или Linux. На Windows используйте WSL с клиентом и Python в одной среде. Внешние пакеты, API-ключи и MCP для базового режима не нужны.

| Клиент | Команда из папки репозитория | Вызов в новой локальной сессии |
|---|---|---|
| Codex | `python3 install.py codex` | `$artem-questioning` |
| Claude Code | `python3 install.py claude` | `/artem-questioning` |

Для установки в один проект добавьте к команде `--project "/путь/к/проекту"`. Установщик копирует одну папку навыка. Если путь уже занят, он покажет его и завершится. Если у вас уже установлен личный Harness Артёма, используйте его экземпляр навыка. Инструкции клиентов описывают доступные расположения. [Codex](https://developers.openai.com/codex/skills/) · [Claude Code](https://code.claude.com/docs/en/skills)

## Первый запуск

Скопируйте запрос ниже. В Claude Code замените первую строку на `/artem-questioning`. Файл учебного кейса можно приложить к чату или открыть репозиторий как рабочую папку.

```text
$artem-questioning
Прочитай только examples/appointments/CASE.md. Владелец хочет отключить мобильную
рекламу. Какое действие обосновано фактами? Покажи, какой ответ изменил следующий
вопрос, и какое наблюдение заставило бы тебя пересмотреть решение.
```

Для своей задачи достаточно описать, **что наблюдаете, какое решение предстоит и куда разрешено смотреть**. Например: «Нет заявок на консультацию. У тебя есть выгрузка событий и обезличенный журнал доставки. Реши, за что браться первым». Для открытой задачи подойдёт: «Как помочь паре выбрать фильм на вечер? Найди три разных механизма и самую дешёвую пробу для каждого».

## Когда задача важная

Можно просто написать: `Это важная задача. Почему заявок мало, а часть обратившихся ожидала другую услугу?` Агент отдельно проверит объём реальных обращений, что обещал вход и что человек получил. У первой найденной причины он проверит остаток: у кого проблема сохраняется даже там, где эта причина отсутствует.

| Режим | Ориентир по вопросам за оба цикла | Максимум новых затратных пакетов |
|---|---:|---:|
| Обычный | до 32 | 3 |
| Важная задача | до 56 | 6 |

Начальный набор — 3–5 вопросов. Следующие зависят от ответов. Один пакет — ограниченный внешний поиск, отдельный проход по сценарию или одно разрешённое задание помощнику. Десятки вопросов к одной сохранённой выгрузке можно обработать локально. Перед затратной проверкой агент называет, какое действие выберет при разных ответах, и резервирует место в очереди. Счётчик сохраняется при возобновлении. Эти величины ограничивают объём исследования, а фактические токены считает клиент.

Проверьте навык на задаче с несколькими причинами и заведомо несопоставимым ориентиром. Сначала передайте агенту только кейс, затем оцените, изменится ли его решение при замене одного факта. [Кейс про выбор фильма](examples/film-choice/CASE.md) · [Критерии оценки из 10 баллов](examples/film-choice/RUBRIC.md)

## Как выглядит работа

| Ситуация | Что делает агент | Что вы получаете |
|---|---|---|
| Причина непонятна | Строит карту объекта, проверяет самые важные независимые условия, углубляет обнаруженные расхождения | Решение с источниками, областью применимости и оставшимися пробелами |
| Новый проект | Восстанавливает путь человека, выясняет, что уже известно, проверяет рискованное допущение | Ближайший выбор и только те вопросы владельцу, от которых зависит действие |
| Нужна идея | Меняет точку зрения, ищет аналоги по функции и случаи, когда привычное решение не помогает | Несколько разных механизмов и наблюдение, по которому можно выбрать между ними |

При глубокой диагностике агент завершает первый цикл даже после ранней находки. Ориентиры — минимум 24 разобранных вопроса, 12 ответов с источниками и 4 дочерние проверки. Если главное решение остаётся открытым, агент разбирает ещё минимум 8 вопросов. Вы можете посмотреть полный Markdown-отчёт. Проверка программы связывает решение с наблюдением в его ветке. Достоверность источника и смысл причинной связи оцениваются отдельно.

## Проверка на своём компьютере

Из корня репозитория запустите два сценария. Демонстрация воспроизводит одну подготовленную ветку, работает офлайн и создаёт очередь во временной папке. Во втором варианте все мобильные заявки дошли до CRM. Сравните «Главное решение» в двух отчётах.

```sh
python3 examples/appointments/demo.py
python3 examples/appointments/demo.py --control
python3 -m unittest discover -s tests
```

Для испытания самой модели дайте ей исходный кейс, сохраните ответ и потом откройте разбор. Оцените, нашла ли она обе причины, избежала ли двойного счёта и изменила ли первое действие в контрольном варианте. Отдельно измеряйте расход токенов в своём клиенте.
