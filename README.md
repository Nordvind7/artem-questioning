# Artem Questioning

Навык для Codex и Claude Code на случай, когда у ИИ уже есть пять советов, а вы ещё не знаете, что случилось. Агент сам задаёт вопросы, ищет ответы в материалах проекта и показывает, какой факт меняет решение.

## А что, если «странная заявка» — это человек, который нас правильно понял?

Учебный пример. Психолог консультирует по видео. Записей мало, и маркетолог собирается сузить аудиторию. Среди обращений ему попалось такое сообщение.

> А можно здесь, сообщениями?

Что увидел человек перед этим? В объявлении — **«Трудно говорить о личном? Напишите психологу»**. На кнопке — **«Написать психологу»**. Его дважды пригласили написать. Он написал. Про видеовстречу узнал из ответа.

Из той же кампании пришло другое сообщение.

> По видео удобно. После семи есть время?

Последнее свободное окно на ближайшие две недели — в 17:00. Представим, что мы уже вписали в объявление слово «видео». **Которого из этих двоих психолог теперь сможет принять?** Первому по-прежнему нужен другой формат. Второму по-прежнему некуда записаться.

Поэтому первый ход — назвать видеоконсультацию прямо в объявлении и показать ближайшие часы до перехода в чат. Если запрос на вечер повторяется, у психолога появляется отдельный выбор — попробовать один вечерний приём или сразу указывать часы тем, кому подходит день. А сужать аудиторию по двум перепискам рано. Сколько людей ушли со страницы молча и почему, по двум перепискам не узнать.

Вот где легко ошибиться ещё раз. После уточнения формата писать могут реже, а записываться чаще. По цене сообщения рекламу в этот момент захочется выключить. По цене подтверждённой консультации она может оказаться выгоднее. **Какую из этих цифр вы хотели улучшить, когда просили «заявки до 500 рублей»?** [Условия, которые можно дать агенту](examples/psychologist/CASE.md) · [Разбор и проверка на другом исходе](examples/psychologist/RESULT.md)

## Что агент делает сам

- **Ищет вопрос, от которого зависит действие.** «Кто наша ЦА?» легко превращается в длинный портрет. А на вопрос «Где до первого сообщения человек мог узнать, что встреча по видео?» можно ответить сегодня, открыв объявление и страницу.
- **Проверяет своё первое объяснение.** Если дело в формате, у кого проблема должна исчезнуть? Второй собеседник согласен на видео и всё равно уходит. Именно этот факт выводит агента к расписанию.
- **Оставляет вам способ его проверить.** Для каждого важного вывода агент указывает источник и объясняет, при каком наблюдении выбрал бы другой ход. В глубоком разборе можно открыть весь список вопросов и посмотреть, на какие агент сумел ответить.

## Где пригодится ТРИЗ

Представьте, что перед записью посетителя просят заполнить длинную анкету. Психологу нужны ответы к началу встречи. Человек ещё даже не знает, есть ли свободный вечер. Команда спорит, сколько полей убрать.

Один из приёмов **теории решения изобретательских задач (ТРИЗ)** — развести противоречащие требования во времени. **Какие сведения нужны, чтобы показать расписание, а какие понадобятся только к началу разговора?** Если календарь можно показать сразу, человек сначала выбирает время. Подробности он добавит после бронирования. Идею проверяют с обеих сторон — стало ли больше подтверждённых записей и успевает ли психолог получить всё необходимое к встрече. [Как применить этот приём к своей задаче](skills/artem-questioning/references/triz.md)

## Попробовать

1. [Скачайте ZIP из последнего выпуска](https://github.com/Nordvind7/artem-questioning/releases/latest), распакуйте его и откройте терминал в папке с файлом `install.py`.
2. Выполните `python3 install.py codex` для Codex или `python3 install.py claude` для Claude Code.
3. Откройте новый чат. В Codex вызовите `$artem-questioning`, в Claude Code — `/artem-questioning`. Приложите [условия задачи](examples/psychologist/CASE.md) и дайте поручение ниже.

   > Собираюсь сузить аудиторию для рекламы психолога. Это важная задача. Изучи материалы и скажи, на что стоит потратить следующий рекламный рубль. Покажи, какой факт изменил твой ответ.

Для своего проекта вместо учебного файла дайте исходное поручение и материалы, к которым агент может обращаться. Для установки в отдельном проекте добавьте к команде `--project "/путь/к/проекту"`. Нужен Python 3.9+ на macOS или Linux. В Windows используйте WSL с Python и клиентом в одной среде. Базовый режим работает на одной модели без дополнительных ключей.

<details>
<summary><strong>Сколько вопросов задаёт агент и как ограничен расход</strong></summary>

Сначала агент выбирает 3–5 вопросов, на которые полезнее всего ответить сейчас. Ответ определяет следующую ветку. Один файл или одна проверка могут дать ответы сразу на несколько вопросов.

| На всю задачу | Обычный режим | «Это важная задача» |
|---|---:|---:|
| Ориентир по числу вопросов | до 32 | до 56 |
| Новые затратные проверки | до 3 | до 6 |

Одной затратной проверкой считается отдельный внешний поиск, проход по пользовательскому сценарию или явно разрешённое задание помощнику. Эти пределы общие для агента и его помощников. Фактические токены считает клиент.

В глубоком разборе первый цикл охватывает все существенные части задачи. Минимум — 24 разобранных вопроса, 12 ответов с опорой на источник и 4 углубления по найденным ответам. Если главное решение остаётся открытым, второй цикл добавляет как минимум 8 вопросов. <details>
<summary><strong>Как проверить навык на своих данных</strong></summary>

Сохраните ответ агента. Измените в исходных материалах один факт, от которого зависит выбор, и повторите запрос в новом чате. Например, добавьте, что второй человек получил ссылку на свободное время в 20:00, но при попытке записи увидел ошибку. В хорошем разборе это изменит предложение по поводу вечернего приёма.

Для технической проверки есть [кейс о доставке заявок](examples/appointments/CASE.md) с [контрольным разбором](examples/appointments/RESULT.md). Следующие команды запускают оба сценария и локальные тесты.

```sh
python3 examples/appointments/demo.py
python3 examples/appointments/demo.py --control
python3 -m unittest discover -s tests
```
